## 1. 深度错位

**现象**：六面外凸/内陷，立方体不成盒，面与边对不上。

**根因**：半长取自尺寸预设的默认值/变量错误，`translateZ` 与实际边长不匹配。

**修法（已落盘）**：六面 `translateZ` 全部 `calc(var(--mc-size) / 2)`；不要在 `:root` 保留独立的 `--mc-half` 预设变量。深度必须与 `--mc-size` 同源。

## 2. 视角与动画互相覆盖

**现象**：点击播放翻转后视角跳变，或动画结束后等轴测角度丢失。

**根因**：视角倾斜和动画 `transform` 写在同一元素上，后写的 transform 覆盖前者。

**修法（已落盘）**：独立包裹层 `.mc-iso-tilt` 承载 `rotateX(-20deg) rotateY(-30deg)`；动画只作用 `.mc-cube` 本体。DOM 顺序：`stage > iso-tilt > cube > faces`。

## 3. 发光/呼吸把立方体压平

**现象**：加了发光或呼吸后，六面被压成一张平面图，3D 深度消失。

**根因**：`filter`（含 `drop-shadow`/`brightness`/`hue-rotate`）加在 `.mc-cube` 上会创建独立的 3D 渲染分组，`preserve-3d` 被扁平化。

**修法（已落盘）**：发光、呼吸、水流、岩浆、传送门、附魔等面级动画的选择器打到 `.face` 叶子元素，例如 `.mc-cube.loop.anim-glow .face`。

**不要尝试**：把 filter 留在 cube 上再调 `transform-style`；也不要在 cube 祖先面板上挂 `backdrop-filter`/`blur`，同样会拍平子树。

## 4. 点击翻转不恢复 / 连点丢类名

**现象**：单次动画结束后常驻循环类丢失；快速连点后旧动画回调把新状态清掉；视角/残留类名错乱。

**修法（已落盘，`playAnim`）**：

- 播放序号 `_mcRun`：每次点击递增，旧动画结束回调发现序号不符直接不执行。
- 暂存 `_mcSaved`：播放前摘下的非一次性循环类，结束后按暂存列表恢复。
- `animationend` 与 `animationcancel` 双监听，动画被取消也能清理。
- 分类数组：`ONE_SHOT_ANIMS`（本体一次性）、`FACE_LEVEL_ANIMS`（面级，不摘取）。

**维护要求**：新增一次性动画必须补进 `ONE_SHOT_ANIMS`；新增面级动画补进 `FACE_LEVEL_ANIMS`。漏登记会导致误摘取或循环类丢失。

## 5. 阴影与居中

**结论（已落盘）**：

- `.mc-shadow` 用 `margin-top: calc(var(--mc-size) * 0.18) auto 0` 下移，匹配俯视角下方块视觉外伸距离；阴影是椭圆径向渐变 + 轻微模糊。
- `.mc-cube` 加 `margin: 0 auto`；画廊容器 `justify-items: center`，保证标签宽于方块时仍居中。

## 6. 顶面贴图灰度/错配

**排查方法**：对照注册表逐一比对顶/底/侧素材；区分「素材本身就是灰度」与「贴图接错面」。

**已确认结论**：

- 草方块顶面素材原本是纯灰度噪声（唯一真异常）：按侧面绿色色阶，以亮度映射重建 16×16 绿色顶面覆盖写回。
- 菌丝体顶面灰紫色是素材原貌，属正常，不要当成错配改绿。
- 原木顶面为年轮图，方向/纹理以素材为准。

**注意**：改贴图前先备份原图；重建像素砖时保持 16×16、`image-rendering: pixelated`。

## 7. 底面薄片外露

**现象**：当前俯视角下底面露出一条薄片。

**结论（已定性，非回归）**：最小对照立方体（标准 transform + `backface-visibility: hidden`）在同一视角/渲染器下同样露出底面薄片，属该视角与渲染器的固有表现。

**保留写法**：底面 `rotateX(-90deg) translateZ(calc(var(--mc-size) / 2)) scale(1.004)`，标准背面剔除。

**已否定方向**：改成 `rotateX(90deg) translateZ(-h)`，矩阵位置等价，并不能隐藏薄片；此类改动已回退，不要重试。

## 8. 素材路径与中文文件名

- `TEX_PATH` 是相对页面文件的素材目录路径，移动项目时同步调整。
- 文件名含中文时，内联 `url("...")` 必须加引号。
- 贴图基本为 16×16 像素砖；`background-size: 100% 100%` 贴合单面，不要引入平滑缩放。

## 9. 圆角凹口 / 角缝透底

**现象**：给 `.face` 加 `border-radius` 后，三个可见面交汇的顶点凹出一个缺口；缺口透出页面背景，或填成一块死黑。

**根因**：
- 三个面都在同一个顶点切圆角，三个四分之一圆之间留下一个三角孔；
- 内芯若用纯色，洞是补住了，但看起来仍像破洞。

**修法（已落盘）**：
- 正对镜头的近顶点保留直角（映射见 `cube-framework.md`「Q 版圆角层」：`front` 的右上、`right` 的左上、`top` 的右下置 0），凹口消失，只把外轮廓磨圆；
- 每个 cube 注入 6 块 `.q-core`：复制对应面贴图、`brightness(0.62)` 压暗、沿法线内缩 3px，缺口处露出的是压暗贴图而不是纯色；
- 内芯必须 `backface-visibility: visible`，否则角缝里看到的是背面、会被剔除成透明；
- 内芯保持方角，不要加圆角，方角才能把缺口完全填住。

**已否定方向**：
- 只减小半径：缺口变小但不消失，16% 时仍明显；
- 内芯用纯色：缺口变成黑色凹角；
- 内芯加圆角：方角填不满缺口，仍透底；
- 三面全圆角再加球面补角：纯 CSS 难以稳定实现，未采用。

**副作用**：近顶点直角写死默认等轴测角 `rotateX(-20deg) rotateY(-30deg)`，换视角（`.iso-2`）需重算；翻转/旋转动画中会短暂看到其他角的直角，属可接受表现。

## 验收清单

改完后在浏览器打开本地页面逐项核对：

1. 四个容器（`#hero-row` / `#effect-grid` / `#glow-gallery` / `#full-gallery`）方块数量与预期一致。
2. 草方块顶面为绿色；原木年轮、工作台/箱子等分面朝向正确。
3. 发光/呼吸方块保持 3D 盒体，没有被压平。
4. 点击方块播放翻转：类名加上 → 动画运行 → 结束后一次性类摘除、常驻类（如 `hover-lift`）恢复。
5. 控制台无报错；连点多次不丢循环动画类。
6. 圆角方案：外轮廓有圆角、近顶点无凹口、角缝无透底；翻转/旋转后方块仍是盒体；发光方块不被压平。
7. 窄屏下栅格换行不破版，方块与标签居中。

浏览器复核方式（本地 file:// 页面）：导航到页面 URL → 读 `console_messages()` → `js()` 统计 `.mc-stage` 数量与 cube 类名 → 截图首屏、特效区、发光区、画廊区比对。
